1. Project Vision

This is NOT only a CERN DRD8 WP4 project. The long-term objective is to build a Personal AI Operating System (Jarvis-like assistant) — intelligent, proactive, multi-agent system for software engineering, AI development, research, browser/terminal/filesystem automation, voice interaction, vision understanding, and multi-agent orchestration.

The CERN DRD8 WP4 pipeline is one capability built on top of this assistant, proving the system can navigate enterprise engineering software, parse industrial CAD, align heterogeneous data, enrich with domain knowledge, and export to physics simulation formats.

Core Philosophy: Local-first, cloud-enhanced. Deterministic automation runs locally (rules handle 80% of cases). Heavy AI inference (Gemini/Claude) runs in cloud. All data stored on F: drive (414 GB free). Offline-capable for core automation.

7. Automation Platform

Desktop Automation (PLM)

PyAutoGUI + Tesseract OCR 5.5. Performance: mouse move ~0ms, screenshot ~130ms, full OCR ~3-4s, record extraction ~3s. Mapped 60+ UI elements for PLM Desktop navigation.

STEP Geometry Parsing

cadquery 2.8.0 / OpenCASCADE 7.9.3. Extracts volume, surface area, bounding box, shape classification (cylinder, plate, block, rod, irregular), aspect ratio, thickness estimate. 30MB (20 solids) → 43s. 2.7MB (17 solids) → 3s. 246MB (917 solids) → timeout >10min.

GDML Export

Custom Python writer producing Geant4-compatible XML. Supports box, tube solids, material assignment, position/rotation, world volume.

Log Rotation

Scheduled task daily at 02:00. Keeps 90 days of logs. Script at F:\OpenClaw\memory\rotate-logs.js.

16. Executive Summary

OpenClaw is a Personal AI Operating System built on a CERN Windows 10 workstation. It orchestrates 4+ autonomous agents (Mission, Coding, Research, CAD) using a multi-agent AGI architecture with Gemini as primary LLM and OpenRouter as fallback.

The current Phase 1 deliverable is a Detector Knowledge Reconstruction pipeline for CERN DRD8 WP4 — extracting engineering data from PLM Desktop (71 fields via OCR/BOM), parsing CAD geometry (37 solids via cadquery), aligning entities across systems (85% confidence), enriching with material physics (27 materials), and exporting to Geant4 GDML.

Working: Desktop automation, STEP geometry parsing (sub-components), material DB, GDML writer, entity alignment (manual), React dashboard (9 pages), comprehensive documentation (30+ tools).

Blocked: Material not assigned for ST0973826_01 — cannot compute physics scoring. Aras API access not granted — stuck with OCR. No native CATIA files — no feature tree/mass. Large STEP file (246MB) times out.

Key architecture decisions: Rules-before-AI (80% rule engine, 20% LLM), local-first with cloud enhancement, markdown-based memory, modular multi-agent orchestration, physics scoring as late stage.

Next move: Contact Diego for material, Aras API client ID, native CAD files, simplified STEP export.

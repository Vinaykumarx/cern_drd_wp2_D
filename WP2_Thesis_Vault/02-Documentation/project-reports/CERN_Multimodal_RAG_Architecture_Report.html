AI-Assisted Knowledge Structuring for Radiation-Damage Materials

1. Executive Summary

This project develops a local-first, multimodal scientific document intelligence system for CERN. It transforms decades of radiation-damage knowledge locked in legacy PDFs (Yellow Reports, IAEA documents, vendor datasheets) into a trusted, searchable, citation-grounded knowledge layer for materials research.

2. Project Overview

What It Is

  • Retrieval-Augmented Generation (RAG) system for CERN scientific PDFs
  • Extracts text, tables, figures, graphs from scanned and born-digital documents
  • Stores vector embeddings in LanceDB with 16-field metadata schema
  • Retrieves relevant passages with cross-encoder reranking (768-dim BGE embeddings)
  • Generates citation-grounded answers through a 3-phase AI pipeline
  • Serves answers via Next.js 15 web dashboard + FastAPI backend

What It Is NOT

  • Not a chatbot — it's a scientific knowledge retrieval + verification system
  • Not cloud-dependent — fully local inference (Ollama fallback)
  • Not a generic RAG demo — CERN-specific architecture with strict citation enforcement
  • Not user-upload based — curated, Nicola-controlled document corpus (~1000 pages)
  • Not experimental — proven at 4th DRD8 Collaboration Meeting (4 June 2026)

11. GPU Strategy & Justification

GPU Usage Profile

OperationGPU RequiredLoad
LLM inferenceYes (primary)Low — 10–15 users
RerankingOptional (GPU acceleration)Low
Embedding generationYes (offline batch)Batch — offline
ColPali multimodalYes (selective)Per-page, select docs
Docling extractionOptional (CPU capable)Offline

Key Message for GPU Request (RQF3798846)

"The GPU resource is required not for large-scale inference load, but for efficient local execution of LLM-based reasoning and reranking within a controlled CERN environment. The system is designed for a small user base (10–15 users) with a curated dataset (~1000 pages), where GPU acceleration ensures low-latency inference, stable batching, and reproducible performance for scientific document analysis."

Recommended Configuration

  • Requested: A100 OpenStack VM (RQF3798846)
  • Backup: L40S (good balanced option)
  • Minimum: A10 (testing only)
  • Key optimization: vLLM batching + KV cache reuse
  • Reality: GPU is NOT the bottleneck — retrieval quality is
